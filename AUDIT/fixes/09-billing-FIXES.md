## ما أُصلح

### حد عدد الطلاب في الباقة أصبح مُطبَّقاً فعلياً
**المشكلة:** صفحة الأسعار تَعِد بـ"حتى 50 طالباً" للتجربة و"حتى 500" للمؤسسي، لكن لا شيء في الكود يمنع تجاوز ذلك. أي مؤسسة كانت تستطيع إضافة عدد غير محدود من الطلاب.

| الملف | التغيير |
|---|---|
| [supabase/tenant_student_limit_migration.sql](../../supabase/tenant_student_limit_migration.sql) (جديد) | عمود `tenants.student_limit` (عدد صحيح، **فارغ = بلا حد**)، مع قيد يمنع القيم السالبة |
| [supabase/schema.sql](../../supabase/schema.sql) | أُضيف العمود لتعريف جدول `tenants` (حسب قاعدة المشروع: schema.sql + migration مستقلة) |
| [src/lib/student-limit.ts](../../src/lib/student-limit.ts) (جديد) | دالة `checkStudentLimit()` مشتركة: تعدّ **الطلاب النشطين فقط** (مطابق لوعد صفحة الأسعار أن الحساب المعطَّل لا يُحتسب) |
| [src/app/api/admin/create-user/route.ts](../../src/app/api/admin/create-user/route.ts) | الفحص قبل إنشاء حساب طالب يدوياً |
| [src/app/api/auth/accept-invitation/route.ts](../../src/app/api/auth/accept-invitation/route.ts) | الفحص قبل قبول دعوة طالب — **هذا المسار الأهم عملياً**: روابط الدعوة العامة متعددة الاستخدام هي الطريقة الفعلية التي كانت ستتجاوز بها أي مؤسسة حدّها |

**قرارات تصميم:**
- **الفحص قبل إنشاء حساب المصادقة**، فالرفض لا يترك حساباً يتيماً يحتاج حذفاً.
- **لا تغيير على أي مؤسسة موجودة:** العمود فارغ للجميع. الحد لا يعمل إلا عندما تضبطه أنت لمؤسسة معيّنة.
- **عند فشل قراءة قاعدة البيانات يُسمح بالتسجيل** (fail-open) مع تسجيل الخطأ في السجل، حتى لا يمنع خلل مؤقت طالباً حقيقياً من الدخول.

## التحقق الحي (على خادم التطوير المحلي متصلاً بقاعدة الإنتاج)
أنشأت مؤسسة اختبار مؤقتة + رابط دعوة طلاب عام:

| الخطوة | الحد | المتوقع | النتيجة الفعلية |
|---|---|---|---|
| طالب A يقبل الدعوة | 0 | رفض | ✅ **HTTP 403** برسالة واضحة بالعربي والإنجليزي |
| هل أُنشئ حساب لـ A رغم الرفض؟ | — | لا | ✅ **0 حسابات** (الفحص قبل الإنشاء فعلاً) |
| طالب B يقبل الدعوة | 1 (لا يوجد طلاب) | قبول | ✅ **HTTP 200** |
| طالب C يقبل الدعوة | 1 (يوجد طالب واحد) | رفض | ✅ **HTTP 403** |

إضافة: `tsc` ✅، `lint` ✅، `vitest` **63/63** ✅. تم حذف بيانات الاختبار كلها بعد التحقق (مؤكَّد بالاستعلام — راجع آخر هذا الملف).

## كيف تستخدمه
لضبط حد لمؤسسة (من SQL Editor في Supabase):
```sql
update tenants set student_limit = 50  where id = '<tenant-id>';  -- باقة التجربة
update tenants set student_limit = 500 where id = '<tenant-id>';  -- الباقة المؤسسية
update tenants set student_limit = null where id = '<tenant-id>'; -- بلا حد (جامعة كاملة)
```
**لا توجد واجهة لذلك بعد** في لوحة مدير المنصة. إضافتها لصفحة `super-admin/tenants` خطوة لاحقة صغيرة إن رغبت.

## ما لم يُصلح من هذه المرحلة ولماذا
| البند | السبب |
|---|---|
| تفعيل صفحة الأسعار (`pricingEnabled = false`) | **قرار تجاري لك**. الأرقام الحالية مكتوب في الملف نفسه أنها "مبدئية" — نشر أسعار غير نهائية للعموم قرار لا أتخذه عنك |
| بوابة دفع (Paddle/Stripe) | تتطلب حساباً تجارياً باسمك، واختيار المزوّد يعتمد على بلد تسجيلك |
| جداول `subscriptions`/`invoices` | بلا بوابة دفع لا فائدة منها الآن. المخطط جاهز في تقرير الاكتشافات |
| سياسة الاسترجاع، DPA، بند القانون الحاكم | نصوص قانونية تحتاج صياغتك/محامياً، وتحديد بلد التقاضي |
