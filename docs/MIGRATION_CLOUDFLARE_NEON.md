# خطة نقل Tilmoo إلى Cloudflare + Neon

قرار المالك (2026-10-21): مغادرة Vercel وSupabase قبل الإطلاق. لا توجد بيانات حقيقية (كل ما في Supabase كان تجريبياً، عدا حساب المالك). القناة الحية مؤجلة. المبدأ: **لا مرحلة تبدأ قبل أن تنجح التي قبلها بالاختبارات**.

## الهدف النهائي

```
المستخدم ──► Cloudflare Workers (Next.js عبر OpenNext)
              ├─ R2: الملفات
              ├─ KV: أدلة المراقبة (موجود)
              ├─ Neon Auth (Better Auth): الدخول والجلسات، والمستخدمون داخل القاعدة
              ├─ Neon Data API: قراءات وكتابات المستخدم عبر RLS (بديل PostgREST في Supabase)
              └─ Hyperdrive ──► Neon Postgres (فرانكفورت): عمليات الخادم المميزة (بديل service role)
```

## ما ثبت بالقياس (2026-10-21)

- نسخة طبق الأصل من هيكل القاعدة الحية في Neon (`tilmoo-trial`): 42 جدولاً، 65 دالة، 59 سياسة، 15 مشغلاً، 114 صلاحية.
- اختبار عزل المؤسسات عبر RLS: 7/7.
- من Cloudflare بجوار القاعدة: معاملة RLS 23–27 ms (الحالي 46–70)، ونحو 290 طلباً متزامناً بلا أخطاء (الوسيط 128 ms).

## الحجم الحقيقي في الكود

211 ملفاً تستورد Supabase · 542 استعلام `.from()` · 43 `.rpc()` · 133 استدعاء دخول · 11 ملفات · 7 قناة حية · 94 مساراً · 99 صفحة · 168 ملف اختبار.

## المراحل

| # | المرحلة | معيار النجاح قبل الانتقال |
|---|---|---|
| 0 | **التحقق من الأسس** على Neon التجريبي: Data API يقبل استعلامات supabase-js كما هي؛ Neon Auth يصدر JWT يقرأه `auth.uid()`؛ الدخول بالمعرّف (member ID) ممكن | كل اختبار تحقق ناجح، وإلا تُعدَّل الخطة قبل كتابة أي كود |
| 1 | **ترقية Next** من 16.3.8 إلى ≥ 16.4.1 (شرط OpenNext) | البناء + كل الاختبارات + lint ناجحة |
| 2 | **تشغيل المنصة على Workers** (معاينة workers.dev) وهي ما زالت على Supabase | كل الصفحات تعمل على Cloudflare بلا تغيير في السلوك |
| 3 | **طبقة وصول موحّدة**: كل استدعاءات Supabase تمر عبر وحدتين فقط (`db` للمستخدم، `admin` للخادم) | الاختبارات ناجحة، ولا استيراد مباشر لـSupabase خارجهما |
| 4 | **الدخول**: Neon Auth بدل Supabase Auth (بريد/كلمة مرور، معرّف عضو، إعادة تعيين عبر Resend، Google لاحقاً) | اختبارات الدخول والأدوار والجلسة ناجحة |
| 5 | **البيانات**: `db` ← Neon Data API، و`admin` ← Postgres عبر Hyperdrive | مصفوفة الأمان (SECURITY_TEST_MATRIX) كاملة على Neon |
| 6 | **الملفات**: R2 بدل Supabase Storage | رفع/تنزيل/صلاحيات ناجحة |
| 7 | **التحويل**: النطاق على Cloudflare، إيقاف Vercel، حذف مشروع Supabase | فحص كامل للإنتاج |
| 8 | **القناة الحية** (مؤجلة): Durable Objects | لاحقاً بقرار المالك |

## ملاحظات إلزامية

- **القناة الحية بين المرحلتين 4 و8**: مراقبة المعلم الحية تعتمد على Supabase Realtime، ولن تعمل بعد نقل الدخول. تُطفأ مؤقتاً بمفتاح، ولا تكسر الاختبار نفسه (المراقبة على جهاز الطالب تستمر).
- **ممنوع D1**: لا يدعم RLS، فيفقد عزل المؤسسات.
- **مصدر الهيكل هو القاعدة الحية لا `supabase/schema.sql`** (الملف متأخر عن الواقع).
- كل مرحلة في فرع وPR مستقل، ولا دمج قبل نجاح CI.
