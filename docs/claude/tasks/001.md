## Rules for this task
1. `loadGroupData` and `loadGroupCards` stop taking a `SupabaseClient`; take `(userId, ...)` and use `run({ as: 'user', userId }, ...)`.
2. Keep the same columns as `GROUP_COLUMNS`, `RECORD_EXAM_COLUMNS`, `RECORD_SUBMISSION_COLUMNS` etc. Embedded selects like `courses(title)` / `users(full_name, email, is_active)` become SQL joins returning the same nested shape the page code expects (or adapt the mapping so the page output is identical).
3. Remove the PostgREST paging helpers (count + pages) — the SQL layer has no row cap. Keep a `limit` on every list (rule 9: bounded lists). Use the same bounds the paging had as a ceiling.
4. Keep `teacher_id = userId` filters exactly; a teacher must never see another teacher's group. If a group is not theirs → same `notFound()` behaviour as today.
5. Schema-qualify tables (`public.groups`). No `select *`. Parameters only via the `sql` tagged template, never string concatenation.
6. Aim: each page = 1 unit (max 2 if the second depends on the first's result). Write the before/after trip count in the progress note.
7. No UI text changes, no styling changes.
