# Security Test Matrix

**Correction:** an earlier summary in this engagement said "13 security
tests." The actual count in `tests/security-auth.spec.ts` is **17** distinct
test instances (5 of them generated by a `for` loop over 5 routes, another 5
over 5 API routes). All 17 were **actually executed live against production**
(`https://eduquest-v2.vercel.app`) this session — not merely written and
assumed to pass.

## Playwright E2E (`tests/security-auth.spec.ts`) — 17/17 passed, live run

| # | Test | Type | Needs 2nd tenant? | Proves a real security boundary, or just an implementation detail? |
|---|---|---|---|---|
| 1-5 | `/teacher\|student\|admin\|super-admin\|center` dashboard → redirects to `/login` | **Live HTTP** (Playwright vs. production) | No | **Real boundary** — proves `proxy.ts` blocks unauthenticated access to every role's route prefix, not just one |
| 6-10 | `POST /api/{admin/create-user,admin/toggle-user,invitations,requests,announcements}` → blocked without session | **Live HTTP** | No | **Real boundary** — proves these 5 privileged API routes cannot be invoked by an anonymous caller (307-intercepted by proxy before the route handler runs, confirmed via direct `curl`, not assumed) |
| 11 | Login page renders email/password/submit | **Live HTTP / UI smoke test** | No | **Implementation detail**, not a security boundary — this checks the page renders, not that anything is enforced |
| 12 | Google sign-in button present | **Live HTTP / UI smoke test** | No | **Implementation detail** — same caveat |
| 13 | Bad credentials → error shown, stays on `/login` | **Live HTTP, real auth attempt** | No | **Real boundary** (weak form) — proves the login form does not silently accept invalid credentials; does not independently verify the Supabase Auth backend rejected them via a network-level check, only via UI outcome |
| 14 | Student → `/teacher/dashboard` redirected away | **Live HTTP, real authenticated session** (`student.test@eduquest.local`) | No — role isolation, not tenant isolation | **Real boundary** — an actual login + actual authenticated navigation attempt, not a mocked session |
| 15 | Student → `/admin/dashboard` redirected away | **Live HTTP, real authenticated session** | No | **Real boundary** — same as above |
| 16 | `X-Frame-Options`/CSP present on `/` | **Live HTTP** | No | **Real boundary** — clickjacking protection, independently verifiable via `curl -I` |
| 17 | `X-Content-Type-Options: nosniff` on `/` | **Live HTTP** | No | **Real boundary** — MIME-sniffing protection |

**None of these 17 require a second tenant** — they test authentication and
role-based routing, not cross-tenant data isolation. **Zero of the 17 are
pure code-level/unit assertions** — every one is a live HTTP round-trip
against the actual deployed production app. Tests 11-12 are UI smoke tests
(mislabeled as "security tests" in the file's own description comment — the
description has been left as-is in the test file itself for now, but this
matrix corrects the classification here).

## Vitest unit tests — 63/63 passed (ran locally, not against production)

| Suite | Count | Type | What it proves |
|---|---|---|---|
| `mutations.test.tsx` + `mutations-extended.test.tsx` | 52 | Component/unit (React Testing Library, mocked fetch) | Cache-invalidation/optimistic-update correctness — **not a security boundary**, functional correctness |
| `password-reset.test.ts` | pre-existing | Unit | Password-reset flow logic — functional, not independently a security-boundary proof |
| `ai-timeout.test.ts` (new, this session) | 6 | Unit (mocked `fetch`/env) | **Real bug caught**: `isAbortError()` originally failed to recognize a real `DOMException` abort (not `instanceof Error`) — a genuine regression test, not a tautology. Proves the timeout wrapper actually surfaces a clean error rather than hanging, and that a timeout never triggers more than one attempt (no retry storm) |
| `ai-rate-limit-circuit.test.ts` (new, this session) | 5 | Unit (mocked Supabase RPC) | Proves the 3-consecutive-failure threshold, the cooldown window, the reset-on-success behavior, and — critically — proves `rateLimit()` (used by cheap endpoints) is **unaffected** by the breaker regardless of failure count, i.e. a DB blip cannot become a platform-wide outage |

**These are unit/mocked tests, not live-database or live-HTTP tests.** They
prove the *logic* is correct in isolation; they do not independently prove
the deployed production code path behaves identically (though the deployed
code is the same source these tests import).

## What remains genuinely NOT TESTABLE this session

- **Live cross-tenant SELECT/INSERT/UPDATE/DELETE attacks** — no second real
  tenant exists in production, and creating one was explicitly withheld.
  Every cross-tenant claim in `SECURITY_AUDIT.md`/`SECURITY_DEFINER_PROOF.md`
  is **CODE-REVIEWED / VERIFIED BY LIVE DATABASE (grants, policies, function
  bodies)** — **NOT LIVE CROSS-TENANT EXPLOIT VERIFIED.**
- **LiveKit room/token cross-tenant exploit** — same reason, plus no live
  proctored session was run.
- **Load/concurrency behavior under real traffic** — see `LOAD_TEST_PLAN.md`
  / `load-tests/`, prepared but not executed.
